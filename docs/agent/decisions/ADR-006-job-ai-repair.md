# ADR-006 作业内嵌诊断与受控修复

日期：2026-10-20。状态：已采用。用户选择作业内嵌助手，底层保留独立诊断工作台的扩展空间；环境验证范围另见验收记录。

## 决定

- 界面沿用现有作业页/抽屉；正常作业可打开AI助手，失败作业显示AI分析。打开仅恢复私有会话，不自动请求模型或查询集群。
- `AiJobService`管理总结与近期消息，`AiJobEvidenceCollector`按需采集已核验归属的配置投影、状态、事件、日志，`AiJobRepairCoordinator`检查并编排确认后的修复。模型只返回建议，不持有写工具。
- SQL创作会话独立保留；运行诊断按用户、jobId和草稿createdAt隔离，重启延续记忆，同名重建隔离。总结最多4000字符；成功保存总结后，超过24条消息裁剪至最近16条，并叠加字符预算。失败保留原文，可重试本轮而不重复追加。
- 复用JSON元数据与主体索引，不新建数据库/迁移。每用户作业只留当前证据、最近2份方案、3份终态应用、5份终态诊断任务；活动/不确定应用先核对，不自动淘汰或另起第二次运行提交。
- 修复采用最多16个标量补丁，只允许资源、并行度和限定Flink参数；身份、namespace、镜像、程序入口、env、凭据及托管下载器不能由模型修改。SQL建议使用完整脚本及原有边界/Parser发布链路。
- 默认仅保存平台草稿，SQL保存不隐式发布。选择保存发布并启动/重启时，明确恢复方式/影响，经集群dry-run后提交最新配置；SQL和配置由同一候选生成，避免旧args或停止快照覆盖新SQL。
- 应用绑定会话版本、SQL/草稿修订和摘要、资源UID及配置摘要；摘要忽略JSON对象字段顺序和数值表示差异。提交复用当前resourceVersion及原操作号；ACCEPTED仅代表受理，实际运行需手动刷新。
- 保存及其阶段状态同事务提交；重试复用原应用号及确定性运行操作号。保存后平台重启或丢响应不重复保存/部署，不自动回滚或降级恢复方式。
- 作业删除同事务清理所有用户该生命周期的AI记录/索引并中断活动诊断，迟到回复不得重建数据。生命周期锁先于SQLite事务取得，避免单连接锁反转。独立SQL草稿、共享Session/文件及既有审计保留各自规则。

## 后果

证据、会话和方案可供未来工作台复用；本次没有常驻监控或跨作业自主操作。外部模型每轮需明确允许发送总结、近期对话、SQL和脱敏证据；自由文本脱敏不能识别任意业务敏感信息。入口与契约见[AI模块](../modules/ai-assistant.md)。
