# ADR-003 平台元数据与运行存储的安全边界

更新：2026-10-13。状态：已采用。来源：最新明确要求、功能/部署文档及对应模块的现有实现。本记录为事后整理，不冒充完整历史讨论或原始选型过程。

- 背景/问题：平台元数据、制品和Flink状态职责不同；换存储或改主密钥可能无法恢复已有数据。
- 决策：元数据SQLite单实例/PVC或MySQL，迁移V1–V5保留；S3存制品及状态，不存元数据库。角色+ACL与Session/CSRF保护操作，密钥静态加密且主密钥稳定，预览/发布各脱敏。
- 原因：延续现有单实例与兼容约束，提供商/插件要按三条真实路径独立验收。
- 重要备选：自动切库搬迁、共享数据等同租户隔离、直接轮换主密钥而不重加密、以MinIO代替厂商认证均不采用。
- 影响范围：数据库、安全、配置、S3、下载器、Flink运行路径。
- 替代关系：2026-10-12：Flink S3 AK/SK在flinkConfiguration中展开，取代10-10转换为主容器环境变量的方案；普通容器env与下载器鉴权保留原规则。Flink S3的既有Secret配置引用按请求读取指定键，源引用仍保留；不新建Secret。

按业务查 [总索引](../INDEX.md) 定位关联需求/代码；参数与完整验收边界不重复抄写。

2026-10-13 补录来源：09-29 用户明确以主清单自动判断数据库文件替代首次安装补丁及手动切换开关。INITIALIZE=true 允许缺失时建库；已有库保留并迁移，不重置已有账号。该行为已核对 StorageConfiguration、SchemaInitializer 与主清单。09-28 密码加密要求不替代 HTTPS，也不改变 BCrypt 或持久化主密钥要求。

2026-10-13 插件与下载器来源补核：10-04 用户后续明确使用实际 Flink 镜像内的插件，并尽量只用 downloader 的一个 initContainer。下载器不能读取另一个镜像的 opt，因此现行方案由下载器准备脚本、Flink 主容器运行脚本，从自身 opt 自动发现唯一 Presto JAR 复制到 emptyDir 再执行原入口。该方案替代 10-02 独立 Flink initContainer 及 10-04 早期共享 S3 插件下载；不新建 ADR，不复活历史已替代方案。插件不存在或多版本匹配必须失败，不从镜像 tag 猜版本。下载器全局唯一绑定的当前实现及历史范围歧义见 REQ-004 与待确认事项。

2026-10-13 本聊天补核：前后端同一单副本 StatefulSet 是10-09明确要求，复用原SQLite PVC；平台SA、用户登录与S3凭据仍独立。最初迁移清单为仅backend投影令牌，当前清单已改为自动挂载，两个容器均可能获得API凭据；自动挂载只是提供身份材料，不授予权限。用户生产环境同namespace并复用Operator SA，不要求强制替换为示例flink-web账号，也不取消按实际资源检查授权的边界。华为S3的WHEN_REQUIRED成功反馈与现行兼容配置分层记录，不升级为厂商完整认证；具体取证限制见 [本聊天核对](../validation.md#sql-与-session-开发聊天归档核对2026-10-13)。
