# ADR-001 按需观测与 SQL 验证例外

更新：2026-10-14。状态：已采用。来源：最新明确要求、功能/部署文档及对应模块的现有实现。本记录为事后整理，不冒充完整历史讨论或原始选型过程。

- 背景/问题：常驻查询会扩大 Kubernetes API 压力，用户明确选择手动查询。
- 决策：作业/Session 进入时查一次，之后 3 秒手动刷新；Session 刷新逐行执行。停止推进由手动刷新/再次操作完成。显式 SQL 验证期间浏览器每 2 秒查结果，后端每 2 秒监听固定日志，保证离页后达到 1000 条仍取消；继续安排截止取消/清理重试和重启恢复。后台只处理已授权的活动验证，不查询列表数量或监控普通作业/Session。
- 原因：保持用户明确的请求边界，同时保证限时验证能结束。
- 2026-10-14：验证日志与控制请求分开做有预算的 I/O，状态锁只处理资格、修订、结果/游标及状态提交；首次取消目标持久化后再请求取消，旧观察失效。预算不代表端到端取消承诺，Kubernetes 身份查询和取消确认仍可能延迟；取消失败继续保留独占并重试，未知提交不能直接视为失败释放。范围仍限定单后端实例和专用 Session。
- 重要备选：常驻watch/轮询、跨页缓存与请求合并不采用；不能删除SQL截止任务来“统一无后台”。
- 影响范围：作业查询、Session、SQL验证、系统Operator查询。
- 替代关系：历史10秒刷新被后续3秒要求替代；当前规则有效。
