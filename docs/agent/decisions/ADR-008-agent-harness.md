# ADR-008 原生工具 Harness 与受控应用

2026-10-30直接开发扩展：按用户最新明确要求，取消 Harness 模型/工具次数上限和逐轮外部授权勾选，保留取消、单次超时、内容大小及角色身份边界。SQL 候选不要求先确认需求；保留初始用户目标与全部留存用户输入，减少反复澄清。实际应用仍需批准具体 SQL 和运行配置；首个无状态运行可在同一入口保存/绑定/发布后按原操作号提交，已有发布作业不借新入口自动重启。此项替代首期“需求确认后才开放 sql_propose / SQL仅保存”规则，旧助手保持兼容。

2026-10-30扩展：新建 SQL 会话不要求已有草稿。空白上下文与候选在批准前不保存业务草稿，批准后将创建/绑定/应用记录原子提交；保留绑定已有草稿与源修订保护。该边界替代首期强制绑定规则。

日期：2026-10-29。状态：接受。关联 [Harness 模块](../modules/agent-harness.md)、[ADR-006](ADR-006-job-ai-repair.md)。

用户要求诊断/开发/评测 Harness，计划先展示，过程默认折叠，正文流式输出；批准后实施参数修改/重启，并控制私有会话脏数据。

采用独立工作台及四个持久化集合，保留旧助手兼容。原生 tool_calls 驱动白名单领域适配器，事件由控制程序产生；不解析模型正文执行命令，不持久化或公开内部推理。模型只产生候选，应用阶段批准具体方案后复用既有身份、修订、dry-run、恢复方式与幂等运行服务。未知提交先核对原号。

单实例采用有界本地队列、每账号单活动任务及数据库快照恢复，网络不入短事务；SSE 投影可重取，取消和删除用 owner/epoch 丢弃迟到响应。实际领域删除与旧助手轮次重置分离。每用户20会话/每会话10轮，删除级联关联评测及产物，保留未结算运行身份。

这是六层能力的可运行基础，评测目前只报告实际轨迹结构。分布式编排、留出集质量评测、任意工具插件和自主生产变更需要后续独立设计，本期不增加消息队列。
