## 验收标准

- 2026-10-15：AI 定义建议逐项检查表/列结构，异常不能标成功，合法但缺连接参数的草稿仍可补全。提交响应丢失先查原请求号；只有用户主动重试且原任务不存在才同号重发，取消未确认仍保留原号。模式、定义或 SQL 上下文变化使旧建议/编译回填失效，历史响应核对上下文与请求版本。一次脱敏仅建立一次局部密钥快照。
- 部署 YAML 的 spec 必须为对象，不能让真值标量通过。Connector 与已用选项匹配排除注释，保留 SQL 原文。日志响应缓冲按实际内容增长，继续保留原尾部大小、传输上限和取消预算。

- 删除部署草稿解除SQL关联，编辑进入关联SQL草稿；保存不自动执行。
- BASIC、精确版本Parser、真实Planner三个层次清楚；缺少适配器不冒充语法通过。
- 专用 Session 仅一个，同时只能验证一份 SQL；累计最多 1000 条变更事件、两分钟取消，不写原 Sink；修改 SQL 使检查失效，Runner 明确选择。2026-10-13 最新要求替代此前 100 条上限。
- 2026-10-14：成功文件的追加结果和事件游标同时提交，后续文件失败不重复计数；不同序号的相同业务值保留。采集整轮五秒预算包含正文传输，取消意图先保存，日志 I/O 不占验证状态锁；迟到观察不得覆盖取消，未知提交和取消重试仍保留单任务独占与 UID/JobID 保护。重启恢复截止任务，结果仍只在内存保留。
- Session/SQL 共用配置编辑状态，统一模式、原文、有效性、脏状态与单调请求版本；编辑后还原也拒绝旧回填，切换草稿/销毁取消旧转换。各自表单及保存、检查、发布流程保留，无法回填或坏响应不得修改原文。

## 10-09 原始开发要求补核（2026-10-13）

本聊天明确移除重复的“执行 SQL”，以部署配置的“部署并启动”为运行入口；删除 SQL 生成的平台作业后解除草稿部署标记，编辑返回对应 SQL 草稿。Session 独立导航支持列表、配置、启停，普通集群可多个，SQL 验证专用集群仅一个。SQL 检查通过才启用“SQL 验证”，内容/配置变化使检查失效；缺少已启动专用 Session 时提供跳转，状态与格式化数据分标签展示，启动失败显示脱敏摘要。
