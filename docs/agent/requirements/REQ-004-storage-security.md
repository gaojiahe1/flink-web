# REQ-004 文件、状态存储、平台权限与元数据安全

更新：2026-10-20。状态：已实现；本地验证范围见 [验收记录](../validation.md)，不代表真实环境/全部版本验收。

背景：制品与状态存储需精确边界，登录/配置/元数据需要权限与兼容保护。

需求范围：存储运行文件及元数据权限两个模块；数据源/Catalog登记规则复用功能文档。 当前完整细则复用 [功能说明](../../features.md)，配置与环境操作见 [部署指南](../../deployment.md)。

## 验收标准

- 2026-10-20追加：作业删除清理当前jobs/id目录及旧版prefix/id目录与精确标记；仅受控UUID，不清相邻或共享文件。停止仍保留目录，集群资源消失才可删除平台作业。

- 2026-10-19：用户要求优化 app 镜像 Dockerfile 并以所提供 BES 11.5.0.006 bundle 替换 Tomcat。保留 Kylin SP3、Java17、非root/只读根、现有 SQLite 路径、Parser/Runner、Session/CSRF 和上传下载；每次从干净基础层构建，禁止基于旧业务镜像累积替换 JAR。源码构建与已验证产物离线构建共用正式 Dockerfile，实际BES启动/非默认端口/临时运行目录须验证。随后要求web/downloader也瘦身、三个镜像统一0.0.7；保留Nginx代理恢复、Python标准库/boto3数据和实际S3下载能力，部署清单同步，实际工作负载更新另行授权。
- 上传拒绝覆盖；目录删除拒绝桶根/穿越/相邻前缀误删；作业删除只清UUID专属程序/状态目录，停止保留。
- SQLite原数据/迁移/主密钥保留，切换MySQL不自动搬迁；角色+作业ACL，Session+CSRF、敏感字段加密。
- 显式Secret引用兼容；环境值按用户要求展开，预览/历史各脱敏；SDK连通不证明下载器/Flink或厂商认证。

关联：[模块](../modules/storage-runtime.md)；[元数据与权限](../modules/metadata-security.md)、[ADR](../decisions/ADR-003-storage-security.md)。关键代码及测试由模块链接定位，不维护第二份路径清单。

## 存储与启动要求来源（2026-10-13 补录）

- 2026-09-21 用户将 GoldenDB 暂改 MySQL，并说明日后自行适配 GoldenDB；09-22 增加 PVC 本地文件模式，09-23 明确默认本地。当前 SQLite/MySQL 实现不代表已支持 GoldenDB。
- 09-28 要求修复登录密码框布局并加密前后端密码传输；当前覆盖登录、用户密码及配置密钥，协议和 HTTP 边界见 [元数据与权限](../modules/metadata-security.md)。不自动加密用户随手输入到普通 SQL/YAML 的任意内容。
- 09-29 用户明确合并首次安装补丁到主清单：数据库缺失时创建，存在时保留。已有库仍执行完整性检查及缺失版本迁移；不要求清空、重置用户或跳过升级。当前独立补丁已删除，主清单 INITIALIZE=true。
- Secret 引用、平台元数据库、S3 文件/状态与 Kubernetes ServiceAccount 分工不能混同。已有 S3 不解决 PVC 中 SQLite 缺失；envFrom 不创建 Secret。初始管理员校验失败与传输加密不是同一问题。

早期“密钥统一转换为 Secret 引用”的实现报告已被 10 月的显式展开规则替代，沿用 [ADR-003](../decisions/ADR-003-storage-security.md) 的最新边界。

## 作业文件与镜像要求来源（2026-10-13 补录）

- 09-30～10-04：文件页采用对象浏览而非制品登记，新上传不创建登记记录；创建前分配 UUID，保存后保持目录一致。复制包含源专属目录中的子目录和未被 YAML 引用的文件，目标路径匹配新 UUID，共享引用保持；新状态目录不复制旧 Checkpoint/Savepoint/HA 或 ACL。删除清完整专属程序/状态目录，停止保留；清理失败保留记录可重试，不能假称对象可随数据库回滚。
- 10-01：下载清单不做 SHA-256 校验，不生成 AWS_DEFAULT_REGION；S3 文件必须有下载器 AK/SK，即使未启用状态存储。纯 HTTP 依赖无需 S3 凭据。此要求不禁止上传/交付哈希、发布仓库摘要或 S3 协议必要 checksum；后续 AWS_REGION 签名兼容见存储模块。
- 10-01 明确下载器与 Flink 镜像独立，一个平台应用只绑定一个下载器；当前实现为系统设置的全局绑定，预览/提交/停止后重建统一选取，不是每条 Flink 镜像记录附加字段。历史关于“平台应用还是每个作业”的追问未见用户单独答复，不能把实现选择记成该追问已得到明确回答。
- 10-02 要求从 Flink 镜像 opt 中复制 S3 插件；10-04 一度实现为共享 S3 文件下载，但用户随后再次明确应使用运行镜像自身 JAR、不猜版本，并仅保留一个托管 initContainer。现行 downloader 准备启动脚本，主容器启动前复制自身 Presto 插件至独立 emptyDir；不要求上传共享插件、不增加第二个托管 initContainer。
- 10-01 用户确认 Kylin SP3 及以上但未指定仓库；四类 Dockerfile 的当前基础镜像通过 KYLIN_BASE 参数提供，默认 V10 SP3。10-02 曾要求指定仓库0.0.4；2026-10-19 明确由 app/web/downloader 统一0.0.7替代，仍不更新latest；更早0.0.5/latest和0.0.4发布记录仅是历史。

S3 密钥先由环境导入配置管理（不覆盖已存在值），状态配置引用变量；后续 Flink 配置内展开的现行表达方式与历史 Secret-env 方案替代关系见 [ADR-003](../decisions/ADR-003-storage-security.md)。来源与历史验证边界见 [本次归档核对](../validation.md#作业与前端修复聊天归档核对2026-10-13)。

## 生产 S3 反馈与诊断要求（2026-10-13 补录）

10-10 用户明确指出仅记录 `S3Exception` 无法排查，要求可用的错误详情。当前 S3FailureDiagnostics 已记录操作、脱敏端点、桶/区域、HTTP 状态、S3 错误码和请求 ID，并保留安全异常链；不能以记录了异常类型代替诊断。该聊天当时因另一任务修改而暂停，未在该回合测试或发布；现有已提交实现与后续历史回归不能倒写成暂停回合已交付。

同日用户明确反馈，生产华为 S3 添加 AWS_REQUEST_CHECKSUM_CALCULATION、AWS_RESPONSE_CHECKSUM_VALIDATION=`WHEN_REQUIRED` 后恢复正常。记为目标环境单次成功反馈，支持校验兼容性判断；缺少原始服务错误码、请求与服务版本，不能证明唯一根因或全部接口、下载器、Flink 状态路径已通过。更换地址/凭据还须核对已保存配置密钥、工作负载和数据迁移，不只重启平台。详见 [存储模块](../modules/storage-runtime.md) 与 [本聊天核对](../validation.md#sql-与-session-开发聊天归档核对2026-10-13)。
