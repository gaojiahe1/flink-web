# 新会话与增量维护

更新：2026-10-13。

## 开始与续接

在当前项目目录打开新 Codex 聊天，适用 AGENTS 会引导先读 INDEX。新需求可直接说“调整 Session 的 JobManager PodTemplate”，也可说明“按索引恢复 REQ-002；核对相关代码后实现……”。继续未完成事项时说“读取当前状态，继续……”，不需要旧聊天持续打开。

指定模块：“恢复 SQL/Session 模块，查看 REQ-003 与相关 ADR，再排查 Runner 验证……”。Agent 从索引选择相关行，读取模块/需求/决策后核对代码与测试；可扩大范围的原因是跨模块、安全影响、索引失效或设计冲突，不能无条件全仓扫描。

## 收尾更新映射

| 任务变化 | 更新 | 通常不更新 |
| --- | --- | --- |
| 已有功能规则变更 | 原REQ、受影响模块、功能说明相关段、current-state | 无关REQ/模块、纯导航索引 |
| 新功能/新路径 | 对应REQ与模块、相关索引项、状态 | 全部知识库 |
| 重要架构取舍 | architecture、相关ADR/索引、模块 | 不相关历史记录 |
| 有长期价值的Bug | 原REQ/模块中的原因、方案、验证；task-log短摘要 | 重复Bug“记忆文件” |
| 部署/镜像/存储参数 | deployment相关段、相关模块/状态；按发布约定执行 | 无受影响组件时不重发镜像 |
| 删除/移动文件 | 对应路径引用、清理依据、受影响索引/模块 | 其他模块结构 |

新证据分代码事实、明确要求、历史报告、推断/待确认；有矛盾时注明来源/日期，最新明确要求优先，再核实实现。原需求变更写一条简短历史，避免多份相互冲突的当前规则。

## 验证后合并 master（2026-10-13 用户要求）

每次代码修改完成后，先通过与改动相应的检查、测试和构建，执行已有的受影响镜像构建、验证、推送及知识库维护约定；验证没有问题后，提交已验证改动，将工作分支合并到本地 `master`。校验失败或未完成时保留工作分支，修复后重验，不先合并再补验证。

合并前核对分支范围和 Git 状态，保护用户未提交改动；同一分支的其他改动也要确认已验证。解决合并冲突或合并结果产生新差异后，对受影响范围重新校验。交付记录说明验证结果、提交和合并结果。只修改知识文档时运行文档检查，不触发代码镜像发布；本规则不自动扩大为远端 Git 推送或实际 Kubernetes 更新授权。

## 补历史与轻量校验

旧聊天只补对未来有用的规则/决策/未完成事项、确认日期和来源。可提供必要摘录或指定聊天；不得整段缓存或复制凭据。未来Agent不能把本轮读过的聊天摘要当完整历史。

路径检查：`python scripts/check_agent_docs.py`。只检查修改文档及直接引用者：`python scripts/check_agent_docs.py --changed docs/agent/modules/job-authoring.md`。修改被导航到的源码路径时把旧/新路径也传入 --changed；首次治理/全局改结构再执行全量知识校验。检查会验证本地链接/锚点，不能证明业务文字始终正确。

检索演示：`python scripts/check_agent_docs.py --demo savepoint`，按索引真实读取文件并输出清单/字节数，不读取聊天或全部源代码。演示结果和增量例子见 [验收记录](validation.md)。不编造Token节省比例。

较大清理另立任务，报告先于删除，中高风险等待明确确认。任务独占临时目录结束回收；不清共享依赖、未知数据库或他人备份。无需定时自动化、后台记忆服务或外部数据库；本任务也未创建定时任务。
